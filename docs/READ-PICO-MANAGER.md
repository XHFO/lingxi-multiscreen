# 小纸 Pico 管理

小纸 Pico 通过“设备管理 → 添加新设备 → 小纸 Pico”添加。填写设备名称，可选填写管理地址；添加后在已添加设备列表与主侧栏显示该阅读器。每台阅读器下有图书、字体、笔记、应用、画板原稿、设备设置、灵犀画板、图片锁屏、固件与备份九个同级入口，内容直接在主窗口展示。多台阅读器分别保存名称与地址，临时配对码仅用于当前连接。

图书、字体、独立笔记先进入 Mac 本地资料库，支持离线导入、缩略图和预览，勾选后再同步到阅读器。设备内的内容、应用与画板原稿可通过已配对的 Wi-Fi 会话或已挂载的 TF 磁盘管理；设备设置、图片锁屏和 Wi-Fi 画板推送复用同一临时管理会话，灵犀画板也支持 USB 有线推送。Pico 为独立管理设备类型，不进入 C6／键盘的卡片轮换和自动推送。

小纸 Pico 等新增设备以多屏灵犀 2.0 测试主线为开发基线，保留 C6 alpha.20 的电脑与本地卡片合并管理。正常交付使用完整 2.0 主程序，启动菜单栏和主窗口。`scripts/make-app.sh` 默认使用测试版应用标识和独立的 `LinxDisplayBeta2` 配置目录，可通过 `LINGXI_APP_OUTPUT_DIRECTORY` 指定候选输出目录。

独立工作台候选仅用于专项调试；该打包方式设置 `ReadPicoStandaloneWorkbench=true`，启动时不读取主软件配置或启动其他设备后台服务。常规 2.0 打包不设置该标记。主窗口使用每台设备独立的会话与草稿，同一设备内切页保留连接与输入，切换设备、返回设备管理或移除设备前经过保存／放弃／取消保护。内置小纸 Pico 固件、TF 应用及校验清单随主程序一起更新。

## Mac 本地资料库

图书支持 EPUB、TXT。EPUB 从原文件提取标题、作者、封面和正文预览，没有可用封面时显示明确占位。字体先显示实际样张并提示缺少中文字形；只允许设备可使用的完整 TrueType TTF，不支持 OTF/CFF、TTC 或 WOFF。笔记支持 TXT、MD，本地保留原文件，同步时转换为 UTF-8 TXT 供设备阅读，不覆盖或合并书内划线、摘录和批注。

导入会保留 Mac 自己的内容副本；删除原来源文件不影响资料库。列表高亮控制预览，复选框控制同步。未连接设备也能导入、搜索和预览；点击同步或打开“设备内”内容时，优先复用已经配对的 Wi-Fi；选择 USB 后才按需准备有线传输。同步显示文件序号、文件名、当前与总字节、校验阶段以及成功、相同跳过或失败结果。同名内容默认保留，替换须明确确认。取消会保留已完成的文件；本地资料和未选中的设备内容不受影响。

## Wi-Fi 与 USB 连接

图书、字体、笔记、应用、画板原稿和灵犀画板共用内联连接面板，可选择“自动”“Wi-Fi”“USB”。自动优先复用有效的 Wi-Fi 内容管理能力；画板自动选择还要求设备明确支持原生16灰阶。强制 Wi-Fi 时不会自动切到 USB，失败会保留当前会话与错误供用户处理。连接方式偏好可保存，临时配对码不会写入偏好。

在 Pico 打开“手机管理”，让 Mac 与 Pico 位于同一网络，在任一内容页、画板或设备设置粘贴设备管理地址和临时配对码即可。完整 `#key=` 地址也可直接配对。切换本设备的功能页时复用同一内存会话；离开设备、明确断开或会话失效后重新配对。旧固件未公开内容管理能力时，提示更新或明确选择 USB。

Wi-Fi 直接访问设备已挂载的 TF 卡，不进入 USB 磁盘模式。列表分页读取，上传以临时文件流式接收，核对 SHA-256 后原子提交；同名不同内容默认拒绝，明确替换才发送 `replace=1`。相同内容通过按需摘要确认后跳过，列表扫描不为每本大型图书重复计算摘要。上传进度的100%表示网络发送完成，仍需等待设备保存及摘要回执。批量取消保留已经完成的文件，未确认的文件应先刷新核对再重试。

无线导出先核对元信息，再下载与校验摘要，验证通过才替换目标导出文件。画板原稿可以导出 DAT、SVG 或 PNG；Mac 不删除原稿。应用安装验证设备目标、稳定ID与CRC；移除应用保留存档。仅允许管理图书、字体、独立笔记、应用和固定画稿路径，不允许任意读写设备配置。

设备管理配对当前有效期15分钟；过期会返回401并要求重新配对。TF未挂载或正由USB独占时返回503，不尝试抢占卡片。单文件最多256MiB，字体最多32MiB、笔记最多16MiB、应用包最多4MiB，还须保留新文件暂存所需空间。Wi-Fi与USB不能同时写TF；开启USB交接会结束旧无线会话。仅编辑离线资料或画板不会主动开启USB磁盘。

| 已鉴权接口 | 用途 |
| --- | --- |
| `GET /api/manage/pico/files?offset=0&limit=64` | 分页列出托管内容，返回 `ok/items/offset/total` |
| `GET /api/manage/pico/file?path=…&metadata=1` | 按需读取路径、字节数、SHA-256 |
| `GET /api/manage/pico/file?path=…` | 下载原始内容，导出时核对摘要 |
| `PUT /api/manage/pico/files?path=…&replace=0` | 原始二进制上传，`X-Pico-Content-SHA256` 绑定提交；返回保存后的路径、字节数和摘要 |
| `DELETE /api/manage/pico/files?path=…` | 移除允许的托管文件，保留应用存档和书内批注 |

这些接口与设置、画板使用同一个 `X-Pico-Setup-Key`，密钥不进入请求URL、日志或持久化缓存，客户端拒绝重定向。HTTP409表示同名保护或存储冲突；503在 JSON `error=home_module_missing` 时表示需安装 `apps/tools/home-link.pga`（薄宿主 Home Link），其余 503 表示 TF 存储暂不可用。均不会改用另一通道继续写入。

## USB TF 卡内容

1. 用数据线连接已开机的小纸 Pico，在侧栏进入“应用”“画板原稿”，或在图书、字体、笔记页切到“设备内”。每台设备的“进入文件管理时自动准备 USB”默认开启；首次核对并确认所选设备后，软件会请求设备开启 USB 文件传输。也可手动点“开启 USB 传输”，或使用读卡器。
2. 等待 Mac 实际挂载磁盘，在上方核对磁盘名称、容量与可用空间并点击“选择此磁盘”。不依赖磁盘卷名，也不把设备的“电脑已连接”当成 TF 磁盘已挂载。曾明确选择的同一卷可在本次设备会话内按卷 UUID 和容量恢复；不自动选择其他外部磁盘。
3. 图书、字体、独立笔记从 Mac 资料库勾选同步；应用可安装内置包或导入兼容包。需要替换同名内容时明确确认。
4. 复制完成后点“安全弹出”。成功后设备会自动接回 TF 卡并检查；若仍停在 USB 页面，再点设备上的“安全结束 USB 传输”。弹出失败会保留当前连接并显示原因，不直接要求拔线。

自动准备只在当前设备的文件管理页可见时发生；隐藏页面不触发。首次确认后以系统只读 USB 序列身份识别本次会话中的同一台设备，同一串口路径换机不会继承信任；缺少唯一身份时需要重新确认。关机、深休眠且没有 USB 枚举时，电脑无法通过软件唤醒，请先点按设备电源。多个串口时由用户选择，不自动尝试所有端口。

本地维护串口先发送只读 `RPICO STATUS` 验证设备与卡片读写状态，再发送 `RPICO USB START`。收到完整的 `accepted=true` 行立即关闭串口；此确认只代表接受交接，之后只观察系统挂载卷，不在 MSC 模式继续轮询串口。USB 准备与固件刷写共用串口租约，互相排斥。开始前处理未保存的设备配置；设备接受交接后清除已失效的 Wi-Fi 管理会话。安全结束后需要重新在设备打开手机管理配对。

等盘超时区分“设备串口已回来”和“电脑尚未挂载”，提供重新检测与停止等待；停止等待不会向设备发送未经支持的 USB 结束命令。取消后不会自动反复发送 START，安全弹出后也不会立即自动重开。TF 拔出或挂载点换卡后清空旧列表，后续写入先核对原目录的文件系统与 inode，防止在旧挂载路径意外创建文件夹或写入另一张卡。

支持 EPUB、TXT 和含 `esp32s3-xtensa` 代码的 PGA1 / ABI1 应用包。导入应用校验头、长度、所有载荷 CRC、稳定 ID、目标平台和保留字段，按包内 ID 放入游戏或工具目录。仅供电脑预览的应用包不能安装到设备。复制先写临时文件并校验，再在同目录原子更名，不把未复制完成的文件作为可启动应用。

“应用”内置五子棋、围棋、象棋、国际象棋、2048、贪吃蛇和画板笔记七个功能包。连接 Wi-Fi 或选择 TF 磁盘后可逐个添加；更新和移除需要确认，独立存档和画板原稿保留。目录来自包内真实标题与版本，加载时核对随软件提供的资源清单、SHA-256 和设备代码。

| 内容 | TF 路径 |
| --- | --- |
| 图书 | 根目录和 `books/`；新导入放在 `books/` |
| 字体 | `fonts/`，仅真正 TrueType TTF |
| 独立笔记 | `books/灵犀笔记-<标题>.txt`，Mac 保留原格式 |
| 游戏 | `apps/games/<id>.pga` |
| 工具 | `apps/tools/<id>.pga` |
| 应用存档 | `apps/data/<id>/`，移除应用时保留 |
| 画板原稿 | `apps/data/drawing-notes/board01.dat` 至 `board12.dat` |

移除图书不删除独立阅读笔记和进度。移除应用同时移除其包备份，避免下次扫描重新出现，但保留独立存档。Mac 不格式化 TF 卡，也不在阅读器本地使用卡片时并行写入。

画板原稿先校验宿主存档头、CRC 和向量格式，可导出精确 `.dat`、可缩放 `.svg` 或 `.png` 副本。导出保留原稿宽高、分笔及橡皮语义。损坏原稿只允许导出原始字节，不作为空白覆盖；Mac 不删除画板原稿。

## 设备设置

在阅读器开启“手机管理”，把包含 `#key=` 的完整地址粘贴到“设备设置”，或填写地址和临时配对码。凭据只保留在本窗口内，不写入 Mac 设置文件、TF 卡或固件备份。

连接后锁定地址和配对码，点击“更换连接”或“断开连接”时先处理未保存设置，再结束原连接。新目标通过身份与能力读取后才显示可编辑设置；失败不会继续向旧设备发送。连接信息旁显示当前实际来源。只有能力接口返回404才兼容旧固件；网络或服务故障不会被当作兼容成功。

- Home Assistant 本地地址、外部地址、家庭 Wi-Fi、外部控制开关和只写令牌使用设备现有管理接口；另支持只写 Cloudflare Access Service Token（`cf_access_client_id` ≤95、`cf_access_client_secret` ≤63），GET 仅回 `has_cf_access_*`，仅用于外部 HTTPS HA，与网页 Cloudflare Analytics 无关。
- 配对先读 `GET /api/manage/pico/status`（含可选 `home_link_mode`：`thin`|`full`|`pga` 与 `home_portal`；缺省按 thin）。薄宿主或 `home_module_missing` 时软降级完成连接，原生 HA 区禁用保存并提示「需安装 apps/tools/home-link.pga」。`pga` 下 home／printers 精确路由写入 PGA 存储（bambu 仍 503）；Mac 表单为备用写入。设备 QR 门户占用 80 口时连接失败提示关闭二维码／等待；写入遇 `409 home_portal_active` 软提示且不提交。门户进行中禁用保存。`GET /api/manage/pico/home-link` 为 pga 聚合回读（full 404）。
- Bambu Lab 登录与验证码、Formlabs Dashboard、实体与房间配置打开设备提供的完整管理网页。网页使用独立非持久会话，限制在当前设备来源。
- 支持新设备接口时，提供六档自动休眠：不自动休眠、1、3、5、10、30 分钟，以及低功耗双击触摸唤醒开关。电源键维持单击。
- Home Assistant 保存期间冻结本次输入；保存后回读设备，核对全部字段及令牌／Access 存在状态后才清空新输入。遇 `home_module_missing` 明确「未保存」，不得提示“设置可能已提交”。验证、写入、回读失败均保留草稿；已提交而断线会明确提示尚未确认。
- 电源配置的 HTTP 202 表示排队；Mac 等待 `state=2`、版本号变化并核对实际值后才显示已保存。失败和未确认超时分别提示，不把请求接收当作保存成功。
- 未保存的 HA 与电源设置共用离开保护。“保存并离开”按 HA 写入与回读、电源确认顺序完成；后一步失败时保留已确认部分，只重试仍未保存的设置。
- 详细网页的完成、Escape、重新读取和全局退出会检查表单修改、进行中的请求及 Bambu 验证码流程。取消保留原页；选择放弃后才关闭。网页自己的确认框由原生窗口承载，账户凭据不回传给退出检查。

## 灵犀画板

“灵犀画板”统一原来的信息推送与电脑画布推送，提供模块、图片、手绘三个来源。模块复用口袋先知画板的添加、移除、拖动排序、单列／双列与整行排布，使用多屏灵犀已有的时钟、天气、正在播放及封面、Mac 监控、Home Assistant 实体等实际数据。每台设备独立保存模块和显示选项，不修改口袋先知或其他设备设置。没有可用内容时不能发送。

画板采用预览与编辑分栏，顶部保留一个“发送到设备”，图片／组件／手绘直接切换，组件点选编辑并支持排序。连接信息从系统自动发现；只有多个设备或无法核对 TF 卡身份时才要求选择。

自动更新需主动开启，默认频率“跟随供电”。充电或满电外接供电时沿用多屏灵犀的动态更新间隔（2 至 60 秒）；电池供电或供电信息失效时结合当前模块的内容检查间隔，避免无意义的检查。可手动选择更新间隔。供电快照超过 45 秒即失效，不会用 USB 插线状态猜测正在充电。USB 直传与局域网使用同一频率规则。

设备确认保存后即可继续后台更新与轮播，只有显示回执才标记“设备已确认显示”。同一设备已交付的图片没有变化时跳过重复上传；尚未显示时只读查询回执。各画板内的独立模块逐项参与轮播。开启自动更新后离开画板页仍继续推送已启用版本；编辑先保留草稿，应用内容后更新自动版本。管理会话结束或出错停止更新。当前设备协议为状态查询及发送回执携带供电快照，没有独立常驻事件订阅通道。

Wi-Fi 推送先连接设备设置，确认固件公开支持原生 16 灰阶、4 位输入和足够大小上限。可选竖屏 684×1216、横屏 1216×684，文字和矢量直接按原生像素绘制，图片按原比例留白，不拉伸。图片导入及草稿重开保留原图像素尺寸，宽长图片不会因 Retina 倍率被误判超限。预览、导出与推送使用同一份 16 灰阶 BMP；旧固件缺少所需能力时提示更新，不自动退化为黑白点阵。

0.35.0-dev58 起 USB 画板通过串口分块直传，不切换 TF 卡所有权，不挂载或弹出磁盘，设备可继续读书。若用户之前打开了 TF 文件管理，先安全交还卡片，再开始直传。明确选择 USB 时按当前连接设备的协议能力验证，不受旧局域网配对身份阻挡；一个传输过程中仍检查设备身份，防止中途换机写错。自动局域网回退 USB 仍核对原目标。旧固件缺少直传能力时提示升级。文件管理继续使用独立的 TF 管理流程。

发送格式为 4bpp、BI_RGB、底向上行序的 Windows BMP，16 项调色板为 0、17、34…255，像素偏移 118，行宽对齐 4 字节，画布接口上限 420000 字节；竖幅为 418422 字节、横幅为 415990 字节。USB 校验长度与 CRC，HTTP 202 只表示接受提交。回执区分保存与显示：自动推送后台接收，不打断阅读、绘画或解锁；手动发送请求立即展示，仍需设备处于可展示状态且不会解除锁屏。画布保存在 TF 卡，设备离线后仍可使用。自定义锁屏使用独立接口，支持 1 位兼容格式和设备明确声明的 4 位 16 灰阶格式，上限 420000 字节。

“保存草稿”将模块排布、原始图片、可编辑手绘与显示选项一起原子保存为 Mac 本地 `.picocanvas` v2 文件；仍可打开 v1 图片／手绘草稿。“打开草稿”先完整验证，再处理当前修改并替换，损坏文件不会清空当前画布。该文件供 Mac 继续编辑，不是阅读器 TF 画板原稿或可安装应用。保存本地草稿不会推送；设备推送只确认当次发送的来源和内容，不会清除另一个来源或后来新增的笔迹。

## 图片锁屏

设备支持时可选择翻页时钟、划线摘录、书库封面、保持当前页面或自定义图片。选择图片后可预览实际输出，设备支持时以4位16灰阶 BMP保存到阅读器的 `/readpico/lockscreen/custom.bmp`，上限420000字节；保留旧1位格式兼容；它与灵犀画板画布分别保存。上传只保存文件，不打断当前显示。设备确认保存后，再选择自定义图片并保存样式，下次锁屏生效。可以读取设备已保存的图片预览；缺卡或图片失效时固件安全回退为当前页面锁屏。

未上传图片参与同一设备的未保存修改保护。取消等待不会承诺撤销设备已接收的写入，只有 `image_lock.state=saved` 且 revision 更新才提示成功。

| 接口 | 用途 |
| --- | --- |
| `GET /api/manage/home` | 读取隐藏凭据的 HA 配置；薄宿主返回 503 + `home_module_missing` |
| `PUT /api/manage/home` | 保存 HA 配置（可含只写 `ha_token` / `cf_access_client_id` / `cf_access_client_secret`）；薄宿主不持久化 |
| `GET /api/manage/pico/status` | 协议 1 的画布、电源、图片锁屏能力及可选 `home_link_mode` |
| `PUT /api/manage/pico/config` | `{auto_sleep_minutes, double_tap_wake, lock_style?}`，原子提交后轮询确认 |
| `POST /api/manage/pico/canvas` | `Content-Type: image/bmp`，上传屏幕原生尺寸的 16 灰阶画布，设备兼容旧 1 位格式 |
| `GET /api/manage/pico/lock-image` | 读取配对设备已保存的真实锁屏 BMP |
| `POST /api/manage/pico/lock-image` | 保存独立锁屏图片，轮询确认，不切换当前页面 |

电源或画布请求已接受后，如果确认阶段断线，显示“已提交，尚未确认”，不会提示为已保存或已显示；重新连接后应核对设备的实际结果。取消等待同样不撤销设备已经接受的请求。

所有请求携带 `X-Pico-Setup-Key`，拒绝 HTTP 重定向，使用无持久缓存会话。旧固件没有新增能力时仍可管理 HA 和打印机，画布和电源配置入口保持不可用。

## 任务与窗口

内容复制、网络保存和画布推送共用忙碌状态。处理期间锁定侧栏切换、表单和关闭按钮，防止更换目标或编辑提交中的内容。可取消的操作提供“取消等待”；本地资料库同步可停止当前复制并清理未提交临时文件，已完成文件保留；其他批量导入显示“停止后续导入”，在当前事务完成后停止。短暂的移除和原稿导出事务不提供中途取消。

同一设备内切换侧栏入口会保留输入。关闭、Escape、窗口关闭按钮和退出应用共用草稿保护，提供保存、放弃、取消；有画布时保存为本地可编辑草稿，有设备设置或待上传锁屏图时等待原阅读器确认。文件选择取消、写盘失败或设备保存失败均留在原页面。最终关闭后才清除连接与临时凭据，迟到响应不能覆盖新连接；退出应用继续沿用原有 C6 与 AWTRIX 恢复流程。

## 微信读书手机授权

在「小纸 Pico → 应用」展开「微信读书 · 书架与笔记」，选择「手机扫码授权」。手机与 Mac 连接同一个可信局域网，扫描引导页二维码；在手机页面打开微信读书官方授权入口，获取 `wrk-` 开头的 API Key，返回填写并保存。Mac 收到授权后，在同一页面读取书架、勾选书籍并读取个人划线与想法，再通过 USB TF 文件管理同步。

二维码打开的是 Mac 临时提供的本地配置页，不要求阅读器同时联网。授权仅保存在 Mac 钥匙串，多台 Pico 共用；设备与 TF 文件不保存密钥。配置会话十分钟到期，成功保存或关闭引导后停止；重新开启会生成新的链接。手机页使用局域网 HTTP，仅在可信网络使用。若手机无法访问，可检查是否连到访客网络，或展开「在这台 Mac 填写」直接授权。

此应用离线展示书架信息和个人划线／想法，微信读书官方接口尚不提供完整正文下载。移除 Mac 授权不删除已同步的设备资料。

### 分区不匹配时的首次全新安装

日常升级只写入应用分区。只有助手确认 ESP32-S3、16 MiB Flash、安全启动和 Flash 加密均关闭，并读到带有效 MD5 的不同分区表、确认旧应用身份为 Read_Pico 后，才会提供首次全新安装。损坏分区表、未知应用或其他芯片不会获得擦除入口。内置首次安装包须包含经过校验的启动程序、分区表、首槽 OTA 记录、系统 APP 和完整初始存储映像。

界面会说明清除内部 Wi-Fi、配对、系统设置及仅保存在内部的笔记和文件，并询问是否继续。取消后不写 Flash；TF 卡不会被擦除。确认与当时的串口、MAC、旧分区表和目标安装包绑定，安装前再次检查，防止确认期间换机、换分区或换文件。开始擦除后禁止停止或退出，随后逐文件独立回读，并核对声明清空的内部区域，校验通过才请求启动。不自动备份旧固件。

首次安装资源使用独立 `fresh-install.json`，不将任意全片转储视作安装包。`scripts/validate-readpico-first-install.py` 供离线资源与打包校验；`--prepare` 根据已构建的固定文件生成初始 OTA 与清单，不访问设备。

### 小纸 Pico 灵犀画板与原生 16 灰阶

设备侧栏的「灵犀画板」统一了原来的信息推送与电脑画布推送，提供模块、图片、手绘三个来源。模块来源复用口袋先知的 `CanvasModule` 与 `ScreenRenderer.renderDeviceCanvas` 引擎：添加、移除、拖动排序，单列／双列及整行模块，独立文字、原图、Home Assistant 实体选择和正在播放封面排布。打印机、天气、系统状态、番茄钟和额度使用多屏灵犀已有的实际数据；不会覆盖口袋先知或其他设备的模块设置。

画面以 684×1216／1216×684 原生像素生成。`rasterScale` 将熟悉的画板逻辑尺寸直接映射到高分辨率绘图上下文，文字和矢量从原始描述光栅化，不先生成 200 像素画面再放大。最终只量化一次到 4 位、16 色、非压缩 BMP：调色板为 0、17、34…255，像素偏移 118，按 Windows BMP 规则逐行补齐。预览、导出与推送使用同一份 BMP。仅在设备能力明确声明原生 16 灰阶、4 位输入和足够大小上限时开放推送，旧固件提示更新，不悄悄退化成黑白点阵。锁屏图片仍走独立协议。

`.picocanvas` v2 保存模块顺序、文字、横竖方向、列数、实体、字号比例、推送间隔、原图及可继续编辑的笔迹；v1 图片／手绘草稿仍可打开和编辑。未提交内容沿用每台设备自己的草稿与离页保护；坏文件先完整校验，失败不会清除当前输入。用户主动开启定时推送后，设备确认保存即可继续下一次后台推送；离开编辑页不会停止已启用版本。后台服务不会因为保存的间隔自动启动。原有时钟、天气、音乐、系统、HA、图片来源会迁移为相应模块。

### 文件与笔记同步冲突

同步先读取两边的完整摘要。大批差异、同名不同内容或笔记记录冲突会显示复核表，提供「合并保留双方」「以 Mac 为主」「以 Pico 为主」。合并为不同版本分配稳定名称；重复同步不会无限追加副本。以 Mac 为主时，先把 Pico 原文件归档到 Mac 并校验，成功后才允许替换。以 Pico 为主时导入设备版本并跳过相应冲突写入。独有文件不会因为优先策略而批量删除。

笔记策略仅协调 Mac 本地笔记数据库；设备笔记接口保持只读。以 Pico 为主会保留 Mac 恢复快照，并提供恢复入口。界面明确说明这一范围，避免用户把数据库优先策略误认为已反向改写阅读器。成功状态在导入文件和缩略图重新载入后才出现。

### 同一快照的双方向画板（dev59）

支持 `canvas.dual_orientation=true` 与 `pair_max_bytes` 的固件一次接收竖屏 684×1216、横屏 1216×684 两份原生 16 灰阶画面。Mac 在同一主线程采样周期、相同 `now` 和摘录记录下生成两种排版；预览方向只选择查看哪一幅，不裁掉另一方向。轮播图片以同一原稿和编辑参数分别适配两个比例。图片、手绘与模块均发送完整双方向快照；自动更新按整套字节比较，只改横屏内容也会更新，单纯切换预览方向不会重复发送。

容器头固定 32 字节：`0..7` 为 ASCII `PICOPAIR`；其余字段均为 UInt32 小端：`8` 版本 1、`12` 头长度 32、`16/20` 竖屏 BMP 长度／IEEE CRC32、`24/28` 横屏 BMP 长度／CRC32，随后依序放置两幅 BMP4。每幅上限 420000 字节，容器上限 840032 字节；原生编码整套为 834444 字节。接收方同时验证两个方向、调色板、尺寸和 CRC，通过后原子替换一整个容器，任何失败保留上一整套，禁止先提交一幅再提交另一幅。设备方向传感器从本地容器选图，不依赖 Mac 再推一次。

| 传输 | 双方向提交 |
| --- | --- |
| USB CDC | `RPICO BOARD BEGINPAIR <task32hex> <bytes> <crcHex> <show0or1>`，后续 CHUNK／COMMIT／ABORT 与单幅事务相同；不导出 TF 磁盘 |
| 局域网 | `POST /api/manage/pico/canvas/pair`，手动展示用 `/pair/show`，类型为 `application/vnd.readpico.canvas-pair` |

自动推送使用后台保存意图，继续保留正在阅读、绘画或锁屏的页面；手动发送才请求立即展示。HTTP 202／USB 接受确认只表示提交被接收；新的统一 revision 与 `saved` 回执确认整套持久化，只有 `displayed` 才确认面板展示。可选 `orientation` 记录当时设备选用的方向。旧单幅接口仍保留兼容，但新版双方向推送在未声明能力时提交前提示更新，不降级、拆包或自动重投。

`Tools/ReadPicoManagerTests/run-canvas-pair.sh` 覆盖容器、精确原生尺寸、CRC、切片 Data、错误方向、截断／溢出、旧能力提交前拒绝、鉴权 HTTP 单次提交和新版本回执。`run-board-session.sh` 覆盖整套去重、横屏单独变化、预览方向切换与图片来源回执；DIRECT PTY 与 Swift→生产 C 接收器集成另行验证同一串口事务。以上为离线测试，不代表实机传感器或屏幕验收。
